# Проверка стабильности

Дата проверки: 29.10.2026. Область — уже реализованные функции приложения.
Журналирование изменений, редактор конфигураций, оформление интерфейса и
повышение физической реалистичности сценариев в эту проверку не входят.
`TASKS.md` и демонстрационные конфигурации не изменяются.

## Исправленные дефекты

| Условие | Прежнее поведение | Исправление и проверка |
|---|---|---|
| Повторный `EmulatorApplication.run()` при запуске или работе того же объекта | Отклонённый запуск закрывал агент первого вызова | Единственный владелец жизненного цикла; проверены параллельный старт и повтор после ошибки привязки порта |
| Community содержит кириллицу или символы вне ASCII | Консоль ошибалась при подготовке запроса либо получала таймаут | Клиент и сервер используют одинаковое кодирование UTF-8; проверены реальные запросы |
| Чрезмерно вложенный YAML | Необработанный `RecursionError` | Ошибка разбора передаётся как `ConfigurationError`; CLI возвращает код 2 без traceback |
| GETBULK содержит больше повторяемых столбцов, чем внутренний предел ответа | Корректный запрос оставался без ответа | Возвращается ограниченный ответ, включая пустой список; проверены 65 и 256 столбцов и последующий рабочий запрос |
| Крупный GETBULK или сочетание non-repeaters и повторений | Возвращался `tooBig`, а ограничение числа значений не учитывало non-repeaters | Возвращается помещающийся начальный фрагмент без ошибки; весь ответ ограничен 64 значениями |
| Длинная community и большое значение | Проверка размера учитывала PDU, но не всё сообщение; ответ не помещался в UDP | Проверяется и полное кодированное сообщение с запасом на максимальную длину request-id; вместо таймаута GET возвращает `tooBig` |
| Ошибка создания SNMP-движка после привязки сокета | UDP-порт оставался занят, пока сохранялся traceback исключения | Сокет закрывается при неуспешной инициализации; проверено повторное связывание порта |
| Сборка использовала setuptools 84.0.0 | Сборочная зависимость не попадала в аудит runtime-зависимостей и содержала известную уязвимость | Закреплена исправленная 84.1.0; CI отдельно проверяет зависимости из `build-system.requires` |

Для GETBULK ограниченный ответ допустим по
[RFC 3416, раздел 4.2.3](https://www.rfc-editor.org/rfc/rfc3416.html#section-4.2.3).
Полный размер UDP-полезной нагрузки IPv4 ограничен 65507 байтами;
учитывается SNMP-заголовок, community и кодирование ответа, а не только значения.
См. [RFC 5405, раздел 3.2](https://www.rfc-editor.org/rfc/rfc5405.html#section-3.2).

## Воспроизводимые проверки

Из рабочего каталога проекта:

```powershell
uv run --locked --all-extras pytest -q
uv run --locked --all-extras ruff check .
uv run --locked --all-extras ruff format --check .
uv run --locked --all-extras python tests/stability_smoke.py
```

`tests/stability_smoke.py` использует только временный порт на `127.0.0.1`.
Он выполняет 600 смешанных GET/GETNEXT/GETBULK-запросов параллельно с передачей
400 воспроизводимых повреждённых датаграмм, затем 20 циклов запуска, запроса
и остановки приложения. Во время циклов отклоняется повторный `run()`, а после
каждого завершения проверяется освобождение UDP-порта. Итог — 620 успешных
запросов, отсутствие необработанных ошибок цикла событий и успешное повторное
связывание порта во всех циклах. Прогон ограничен по объёму и не является
проверкой предельной производительности или гарантией защиты от сетевой перегрузки.

Дополнительно проверяются запрет изменения метрик через SET, неверная community,
неподдерживаемые запросы, границы OID и числовых значений, переполненные ответы,
неизвестные OID, отмена запуска, ошибки конфигурации и сохранение значений после
duration. Безопасный YAML-загрузчик отклоняет создание Python-объектов.

CI проверяет Linux Python 3.11–3.13 и Windows Python 3.13, метаданные и сборку,
установленные wheel/sdist, GUI и реальный Net-SNMP. Проверка стабильности
добавлена к установленным дистрибутивам. GUI-тесты на Windows скрыты; отдельная
проверка клавиатурных событий с отображаемым окном выполняется под виртуальным
дисплеем Linux, чтобы не перехватывать фокус пользователя.

Аудит зависимостей проводится по `uv.lock`, включая тестовые и проверочные
зависимости, а также отдельно по `build-system.requires`. Обнаруженная
[GHSA-xmj3-9gf7-h52w](https://github.com/advisories/GHSA-xmj3-9gf7-h52w)
относится к выходу за каталог установки в устаревшем пути установки wheel
в setuptools на Windows; это не подтверждённая удалённая уязвимость
SNMP-сервера. После обновления сборочной зависимости до 84.1.0 оба аудита
успешно пройдены без исключений уязвимостей из проверки.
Workflow проверяется zizmor; отсутствие находок не заменяет анализ поведения
приложения.

## Границы стабильной точки

- Подтверждённая среда — Python 3.11–3.13, IPv4/UDP, SNMP v2c, локальные
  конфигурационные файлы и предусмотренные схемой значения.
- SNMP v2c использует community без шифрования. Публичное сетевое размещение,
  защита от подделки UDP-адресов и ограничение частоты запросов не реализованы.
  Готовые примеры слушают только `127.0.0.1`.
- Проверки не доказывают отсутствие всех возможных ошибок и не охватывают
  зависшие сетевые файловые системы, исчерпание памяти или произвольные
  отказы операционной системы. Долговременная эксплуатация и предельная
  нагрузка требуют отдельной проверки в целевой среде.
- Движок выполняет заданное расписание, а не физическую модель устройства.
  После окончания сценария значения сохраняются до остановки — это контракт
  приложения, а не моделирование дальнейшего поведения оборудования.
- Оставшиеся функции из `TASKS.md` не объявляются реализованными по результатам
  стабилизации.
